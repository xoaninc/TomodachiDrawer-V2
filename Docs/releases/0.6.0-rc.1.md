# TomodachiDrawer V2 0.6.0-rc.1

This is a **pre-release for Switch testing**. The new bucket behaviour has not been validated
on a real console. Version 0.5.0 remains the latest stable release.

## Changes

- Integrates upstream 0.9.2's brush/bucket timings, per-layer cost comparison and reuse of
  already painted borders. V2 retains parallel route generation and its routing optimizations.
- Adds **Enable Bucket Fills**, a separate persisted checkbox, **off by default**. Each layer
  compares an ordinary painting plan with an outline-and-fill plan. Only the selected plan is
  emitted. Preparing both alternatives can increase generation time.
- Fixes early-exit settings being ignored by parallel route solves.
- Prevents overlapping generations from replacing each other's cancellation token. Checks
  cancellation before exporting and before retrying an RP write; the ESP32 flash phase disables
  the generation-cancel button once flashing starts.
- Updates Avalonia to 12.1.2 and SkiaSharp plus matching Linux assets to 4.151.2.
- Handles release-candidate version ordering in the update checker and labels HID timing
  estimates as nominal.
- Fixes startup handlers overwriting saved preferences before loading them. Releases replaced
  preview images, opens export error dialogs on the UI thread, and clears the in-progress
  estimate label after cancellation.

## Validation

The local Release test suite passes **222 tests**, including 320 repeated small drawing
generations across serial/parallel modes, strict TDLD decoding, toolbar timing, candidate
isolation and cancellation boundaries.

The focused four-version comparison passes **38/38 drawings** with exact pixels, matching
source/reference hashes, strict command decoding and equal v3/v4 payloads for the same V2 route.
It includes the real photo, all four candidate thread modes, buckets off/on and three synthetics.
The original 624-run matrix was stopped for time and remains incomplete.

On the real photo in production mode, buckets-off generation is 4.228 s median versus 4.232 s
on prior main; nominal drawing time is 4651.525 s versus 4661.025 s. Buckets on reduces the
candidate's nominal drawing time to 4312.925 s, generating in 7.814 s. These are measured examples,
not universal speed guarantees. See [the comparison report](https://github.com/xoaninc/TomodachiDrawer-V2/blob/0.6.0-rc.1/Docs/COMPARISON_0.6.0_RC1.md).

GUI checks cover saved settings through restart and cancellation followed by export. CI gates
publication on Debug/Release builds/tests, comparison-harness guards, ESP32 parser checks and
reproducible RP firmware builds. Upstream 0.9.4 was separately reviewed and deferred.

## Trying it

Download the package for your OS and architecture and extract it before opening the app.
Generate a fresh drawing. Start with dynamic buckets and HID polls **off**, inspect the initial
erase-all/background fill, then complete the previously failing image.

The initial background fill is separate from optional per-layer buckets. Its Switch 1 support
and the additional menu waits also require a real-console check.

The RP2040/RP2350 firmware is unchanged from V2 0.5.0. TDLD v3 remains the default; opt-in HID
poll timing remains RP-only and uses v4. ESP32 exports force v3. Explicitly longer menu taps
retain millisecond durations in both formats.

**Cancel Generation stops computation on the computer.** Unplug the board from the Switch to
stop a drawing already running there. Offline pixel equality cannot prove menu coordinates or
that the console received every input.

Follow [the hardware checklist](https://github.com/xoaninc/TomodachiDrawer-V2/blob/0.6.0-rc.1/Docs/HARDWARE_VALIDATION_0.6.0.md)
and keep the application log and a photo of the finished canvas with the exact settings used.
